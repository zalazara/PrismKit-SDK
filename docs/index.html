Measure SwiftUI layout while it runs.

Prism Inspector reads a running app in the iOS Simulator and lets you work on it the way you work in a design tool: click an element to inspect it, ⌥-click a second one to measure the space between them, and see immediately when that space is not on your design system's scale.

What it does

Everything below is a screenshot of the tool doing the thing, against a real app running in the simulator — so what you measure is what the app actually rendered, not a guess from a picture of it.

Measure like a design tool

Click an element to select it. ⌥-click a second one to measure the space between them — the gap per axis, or the four insets when one contains the other.

Distances come from the layout the app actually produced, in points. Nothing is counted by eye off a screenshot.

Check the screen against the design

Attach a design and get a per-node report: what moved, what is the wrong size, what is missing. Expected positions are drawn straight onto the canvas, beside where the element actually landed.

When something has no match, the nearest unclaimed element is offered with it — because "it moved" and "it disappeared" look identical to a comparison that only matches by position, and only one of them is the bug you are looking for.

Hear what VoiceOver hears

Play the screen back in the order VoiceOver reads it, with each element outlined on the canvas as its announcement is spoken and highlighted in the list.

An unlabelled button stops being something you audit for and becomes something you notice: it is the one that says "Button" and nothing else. Trait words come from the traits SwiftUI already set, so they are what a real user would hear — in the reading language you pick, which is separate from the interface language.

Your spacing scale, not ours

Paddings and gaps are flagged when they fall off your scale, with the nearest token as the hint. It lives in a .prismkit.json you commit, so the app, the MCP server and the whole team judge by the same numbers.

No instrumentation required

Point it at a running app and inspect the view tree straight away. The SDK is optional — it upgrades readings from UIKit's class names to the component names you chose.

Mockup side by side

Put a design image beside the running app, overlay it with adjustable opacity, or wipe between the two — with the guides mirrored across both.

Rulers, guides, overlays

Drag out guides, toggle grid, safe-area, layout-column and concentric-corner layers. All off by default, so the canvas starts clean.

Export and save sessions

Export the canvas exactly as you see it at native device scale, or save a session and review it later with the simulator closed.

Six languages

English, Spanish, Portuguese, Chinese, French and German — interface, help and the accessibility reader.

Get started

The first three steps are the whole tool. Everything after them is optional and can wait until you want it.

  1. Install it

    Download the disk image, then drag Prism Inspector into Applications in the Finder — dragging matters. An app copied any other way keeps the quarantine flag macOS puts on downloads, and macOS then runs it from a random read-only folder, which stops it updating itself later.

    The first time you open it, macOS asks you to confirm because it came from the internet. That prompt is normal: it also says Apple checked the app and found no malware, which is what notarization means.

  2. Run your app in the simulator

    Any SwiftUI app, from Xcode or simctl. Nothing to add to your project and nothing to configure.

  3. Open Prism Inspector

    It finds the running app and mirrors its screen. Click anything in the canvas or the view tree to inspect it, ⌥-click a second element to measure between them, and press Esc to deselect.

    Order does not matter. Start either one first — the app reconnects on its own within a few seconds.

  4. Turn on accessibility reading — optional

    iOS only builds the accessibility tree while the system accessibility flag is on, so the reader has nothing to read until you enable it. The app has a button that does it for the selected simulator; the app has to be relaunched afterwards.

    Without it you still get geometry — sizes, spacing, the view tree — just not labels or announcements.

  5. Name your components — optional

    Add the package and mark the views you care about. Readings stop saying CGDrawingLayer and start saying what you called them, and padding becomes measurable as padding rather than as the gap between two boxes.

    dependencies: [
    .package(url: "https://github.com/zalazara/PrismKit-SDK.git", from: "0.2.0")
]
    ProductRow(item: item)
    .measure("productRow", role: .container)

    All of it compiles out of release builds. Nothing ships to the App Store and no user data leaves a device.

  6. Declare your spacing scale — optional

    Drop a .prismkit.json in your project and point the app at that folder once. From then on the app, the MCP server and anything an agent reports all flag spacing against the same numbers instead of a built-in default that is not your design system.

    {
  "spacing": [4, 8, 12, 16, 24, 32, 40, 48, 64],
  "grid": 8
}

    Commit it, and the whole team judges spacing the same way.

  7. Connect an AI agent — optional

    Open Settings ▸ AI agents and copy the JSON shown there into your MCP client's configuration. The path is already filled in, because the server ships inside the app — there is nothing to install or build.

    The app and the server both listen on port 9294, so only one runs at a time. To use both at once, set PRISMKIT_PORT for the server.

The SDK is optional — and open

PrismKit is the Swift package you add to your app when you want measurements named after your components instead of after UIKit's internals. 

dependencies: [
    .package(url: "https://github.com/zalazara/PrismKit-SDK.git", from: "0.2.0")
]
ProductRow(item: item)
    .measure("productRow", role: .container)
  • MIT licensed, and the source is right here in this repository.
  • Compiled out of release builds: the measurement code, the accessibility walk and the network client all sit behind #if DEBUG, so nothing ships to the App Store and no user data ever leaves a device.
  • Works in Xcode previews as well as in the simulator.

Built for AI agents too

Prism Inspector ships an MCP server inside the app bundle, so an agent can read the same measurements you see and report what does not match the design.

  • get_measurements, measure_distance, check_alignment — the numbers, straight from the running screen.
  • attach_design, compare_to_design — hand it a design and get the differences back as structured findings rather than prose.
  • get_design_tokens, set_design_tokens — the same spacing scale the app judges by.
  • list_simulators, capture_screenshot — for driving the simulator.

The app's Settings ▸ AI agents pane shows the exact JSON to paste into your MCP client, with the bundled server's path already filled in.
